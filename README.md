# MSA-2020 (Microsoft A-2020) FPGA Board Experiments

**English** | [中文](README.zh-CN.md)

Open-source experiment projects and host-side tools for the decommissioned
datacenter FPGA board **MSA-2020** (Microsoft Catapult A-2020,
Stratix 10 `1SG280LN2F43E2VG`).

**Projects 7–10 form a video compute accelerator** (image preprocessing + video
filtering + AI pre-processing + codec transforms + framebuffer, all riding on
the already-verified PCIe BAR framework). Workflow: **first simulate with
iverilog against a bit-exact Python reference, then compile in Quartus** —
this flow caught two BRAM read-latency bugs of the same kind (FSM missing a
wait state) before compilation. See [VIDEO_ACCEL_TOMORROW.md](VIDEO_ACCEL_TOMORROW.md)
for the flash-and-test guide.

> **Project 10 debugging war story** (two stacked bugs; broadly useful for any
> "simulation passes, silicon fails" situation):
> ① Non-deterministic encoder output = a hand-written AXI-Lite asynchronous
> clock-domain-crossing handshake with insufficient margin → refactored into a
> **dual-clock true-dual-port BRAM + single-bit synchronizers**
> (`h264_wrap_dc.v`, reads and writes separated in time); the non-determinism
> disappeared.
> ② Still deterministically wrong after the fix (541B vs. 168B in simulation) =
> `cur_mb.v` was missing `` `include "enc_defines.v"``: iverilog/Questa treat
> all files on the command line as **one compilation unit** (macros leak across
> files, so the 64-bit ports were correct), while **Quartus Pro compiles each
> file as an independent compilation unit** → `` `BIT_DEPTH`` undefined → the
> pixel port collapsed to 9 bits. Fix = add `VERILOG_MACRO "BIT_DEPTH=8"` to
> the qsf. The clue had been sitting in the synthesis warnings all along
> (`16735: actual bit length 64 differs from formal bit length 9`) —
> **audit every width-mismatch warning, one by one**.

> **A note on H.264/H.265**: a complete H.264/H.265 codec cannot be hand-written
> from scratch (motion estimation + CABAC + deblocking filter are giant IPs).
> Project 8 delivers its mathematical core, the DCT/IDCT; project 10 integrates
> the real open-source core xk264. **The xk264 sources are NOT included in this
> repository** (its license forbids redistribution — `git clone` it yourself);
> this repository only contains the integration docs, the project qsf, and my
> original FPGA memory library `mem_fpga/` (replacing its ASIC tri-state
> models). H.264 is also covered by the MPEG-LA patent pool; shipping
> commercial products requires a license. For H.265, the only open-source
> hardware is uvgKvazaarHW via an HLS (Catapult) flow — there is no pure-RTL core.

Each project directory is self-contained (Quartus project + RTL + host scripts
+ README). Open each `.qpf` with Quartus Prime Pro 23.3 to compile, or flash
the bundled `.sof` directly. (Project 4 is a collection of sub-projects; see

## Board Essentials (shared across experiments — hard-won lessons)

- **JTAG limitation**: the on-board FT232H uses a Catapult custom driver
  (`jtag_hw_microsoft_catapult.dll`) that only supports programming and simple
  shifts; System Console's JTAG-Avalon streaming **hangs permanently**.
  All host communication therefore goes through **ISSP** (single-shot shifts),
  measured stable at ~150 ops/sec.
- **VID power configuration** (`PWRMGT_*`, SDM pins) **must** match the
  official blink example — a wrong configuration can destroy the board. Every
  qsf here already includes it; do not modify.
- **DDR4**: **4 independent channels**, DIMM0/1/2/3 ↔ `ddr4_mem[2]/[3]/[0]/[1]`
  (CK pins AP10/L6/AU22/K31); each channel routes only 9 DQS groups + 1 chip
  select → **only 1Rx8 is supported** (x8 devices, single rank), capped at
  2400MT/s. See the 2_EMIF README for dual-channel details.
- **DDR4 calibration root cause** (details in the 2_EMIF README): the RDIMM's
  PAR/ALERT_n must be connected; let the EMIF IP derive the timing parameters
  (TCL/WTCL) automatically — do not lock them by hand.
- Board-level shared I2C: `SCL=AC28 / SDA=AB28` (3.0-V LVTTL), hosting the
  DIMM SPD (0x50), FPC202, DS250DF810 retimer, etc.
- **QSFP0 transceivers** (25.78G GXT): refclk `AD34` (644.53125MHz); TX/RX are
  wired to **non-contiguous physical channels 0,1,3,4** (designed for 4×25G
  independent lanes, not bonded 100G). The correct topology = Corundum
  520N_MX (master ATX + atx_blw buffer + iqclk refclk), `anlg_link=sr`.
  See the READMEs inside projects 4 / 5.
- 100MHz user clock on `PIN_AD6` (1.8V); for the same board also see
  [SuperSodaSea/Plugcat](https://github.com/SuperSodaSea/Plugcat).
- **PCIe**: Gen3 x16, `TX BB34..` / `RX AV30..` / refclk `AM34` / perst `AC26`.

## Host Environment

Windows + Python 3 + Quartus Prime Pro 23.3 (syscon as the JTAG back-end).
On first use, install the FTDI D2XX driver per the board's documentation
package and copy the custom dll into `quartus\bin64`.
(Note: the **NIC driver for project 5 Corundum mqnic is Linux-only**; on
Windows you can only verify PCIe enumeration — see
`5_Corundum_fork_on_MSA2020/HOST_VALIDATION.md`.)
